# AGENTS.md — Hostal Los Carrera

Next.js 15 (App Router) + React 19 + TypeScript + Tailwind CSS v4 + Framer Motion 12.
Landing page for Hostal Los Carrera, a white guesthouse in Copiapó (Chile) with private-bathroom rooms. Built from the same code as the GeoRig site (`../georig`). The site owner is not a developer and edits it through AI assistants (in Spanish; see `EDITAR.md`).
Keep the content contract below intact.

## Where things live

- `src/lib/content.ts` — every visible string, every asset URL (`MEDIA`), every section background (`BACKGROUNDS`). Keys in English, comments in Spanish: keep it that way.
- `src/app/globals.css` — colours (`@theme` block) and fonts.
- `src/sections.ts` — section registry (order + `active` flag).
- `src/lib/frame.ts` — `dw()`/`mw()` design-canvas units for the hero (1440×810 / 440×956 → `cqw`).
- `public/brand/` — logo, logomark, key emblem, arcs SVG and placeholder illustrations (`photos/*.svg`, generated by `scripts/ilustraciones.py`; replace them with real photos), all referenced only through `MEDIA` (`asset()` prefixes `NEXT_PUBLIC_ASSET_BASE` when set).

## Four hard rules (content)

1. **No component may contain a visible string.** Every string is a key in `content.ts`; components read the key.
2. **No component may contain an asset URL or path.** Everything goes through `MEDIA`. The single exception is `PILL_MASK` in `src/lib/assets.ts`: it is an embedded `data:` URI because it is consumed via `mask-image`, and Chrome silently drops cross-origin SVG masks. Never move it to `MEDIA` or the asset bucket.
3. **`HeroDesktop` and `HeroMobile` share zero duplicated content.** They are two separate, always-mounted trees toggled by CSS (`hidden md:block` / `md:hidden`) — never a `matchMedia` fork — and both read `HERO` and `MEDIA`.
4. **No hex colour outside the `@theme` block** of `globals.css`. Exceptions: Next metadata `themeColor` (cannot take `var()`) and hex inside documentation comments. Note `public/brand/arcs.svg` is an asset, not code.

## Three wiring rules (backgrounds)

1. **Exactly one `<SectionBackdrop>` per section that has a background**, and it is the only place a background `<video>`, full-bleed `<img>`, veil, `.grain` or vignette may appear. In this build: `HeroDesktop` (`BACKGROUNDS.hero`), `HeroMobile` (`BACKGROUNDS.heroMobile`) and the body wrapper in `app/page.tsx` (`BACKGROUNDS.body`), each with `className="-z-10"`.
2. **The hero's artboard decoration is NOT a backdrop layer.** Halos and ground marks are positioned artboard layers with nested negative-inset bleed boxes on `dpx()`/`dpy()` coordinates; only their URLs live in `MEDIA`. Coordinates are design, not content.
3. **Nothing outside `SectionBackdrop` reads or writes the `<video>`.** Follow it with `onProgress`, move it with a `control` ref. Keep both props even though this build has no video.

## Also

- Hero headline: "H" + an accent ring standing in for the "O" + "STAL" (reads "HOSTAL"). The `brandParts` keys are still `ge`/`rig`; `GE_W` is the measured width of "H". The ring is drawn twice: the full ring before `PhoneMockup` and a `clipPath: inset(52% 0 0 0)` copy after it, so the phone sits inside the "O". The desktop ring is scaled with `KX`/`KY`; its masked inner shadow (`PILL_MASK`) is stretched with the same factors — change both together.
- `PhoneMockup` is DOM sized in `em` (29 × 60 em); callers set `fontSize` with `dw()`/`mw()`. Its strings come from `HERO.phone`.
- The hero `.frame` element (`container-type: size`) must stay the direct parent of every positioned hero layer; without it `cqw` resolves against the viewport and the hero renders oversized.
- The accent colour is sky blue but its tokens keep the `--color-gold*` names (and Tailwind classes `text-gold`, `bg-gold`…); change the values, not the names.
- Removing a section = `active: false` in `src/sections.ts`, not deleting the line.
